# Данные ЕГР в формате JSON

## Структура данных

JSON файлы в этой директории содержат **базовую информацию** о компаниях из ЕГР, полученную через API `getBaseInfoByPeriod`.

### Что содержится в JSON файлах:
- `ngrn` - УНП компании
- `dfrom` - дата регистрации
- `dto` - дата ликвидации (если есть)
- `nsi00219` - статус компании (действующий, ликвидирован и т.д.)
- `nsi00208` - способ создания
- `nsi00211` - тип объекта (юрлицо или ИП)
- `nsi00212` - регистрирующие органы
- Прочие метаданные

### Что НЕ содержится в JSON файлах:
- ❌ **Названия** компаний (требуется дополнительный запрос)
- ❌ **Адреса** (требуется дополнительный запрос)
- ❌ **Коды ВЭД** (требуется дополнительный запрос)
- ❌ **История изменений** (требуется дополнительный запрос)

## Процесс загрузки данных

Для полной загрузки требуется **3 этапа**:

### Этап 1: Загрузка base_info из JSON
```python
from app.tasks.sync_tasks import load_companies_from_json
result = load_companies_from_json()
```

Результат: записи в таблице `egr_raw_company_data` с полем `data = {"base_info": {...}}`

### Этап 2: Обогащение через API
```python
from app.tasks.sync_tasks import enrich_missing_raw
enriched = enrich_missing_raw(limit=10000)
```

Что происходит:
- Для каждой записи вызывается `get_full_company_history(unp)`
- Добавляются поля: `addresses`, `names`, `ved`
- Обновляется `egr_raw_company_data.data`

### Этап 3: Обработка в структурные таблицы
```python
from app.tasks.sync_tasks import process_pending_raw
processed = process_pending_raw(limit=10000)
```

Что происходит:
- Парсинг данных через `CompanyMapper`
- Сохранение в таблицы:
  - `egr_companies`
  - `egr_company_names_history`
  - `egr_company_addresses_history`
  - `egr_company_ved_history`
  - `egr_company_contacts_history`

## Проверка статуса

### Сколько записей загружено?
```sql
SELECT COUNT(*) FROM egr_raw_company_data;
```

### Сколько записей требуют обогащения?
```sql
SELECT COUNT(*) 
FROM egr_raw_company_data 
WHERE NOT (data ? 'names') 
   OR NOT (data ? 'addresses') 
   OR NOT (data ? 'ved');
```

### Сколько записей обработано?
```sql
SELECT COUNT(*) FROM egr_companies;
```

### Сколько записей с ошибками?
```sql
SELECT COUNT(*) 
FROM egr_raw_company_data 
WHERE last_error IS NOT NULL;
```

## Формат файлов

Файлы именуются по периоду регистрации компаний:
- `01.01.1900-01.01.1990.json` - компании, зарегистрированные с 1900 по 1990 год
- `01.01.1990-01.01.2000.json` - с 1990 по 2000
- и т.д.

Каждый файл содержит массив объектов:
```json
[
  {
    "ngrn": 100380804,
    "dfrom": "1975-06-12T21:00:00.000+00:00",
    "nsi00219": {
      "vnsostk": "Действующий",
      "nksost": 1
    },
    "nsi00211": {
      "vnvobp": "Юридическое лицо",
      "nkvob": 1
    }
  }
]
```

## Очень большие файлы (1+ ГБ)

Файл 1.5 ГБ и больше **не загружается целиком в память** — используется потоковый разбор (ijson). Задача импорта имеет лимит **8 часов**, этого обычно хватает на 1–2 ГБ.

**Рекомендуемый способ** — разбить файл на части по ~100–200 МБ, затем импортировать части как обычные файлы:

```bash
# Разбить большой файл на части по 100 МБ (без загрузки всего в память)
python scripts/split-large-json.py data/egr_json_full/31-12-1989-30-12-2025.json --size-mb 100

# Удалить или переместить исходный файл, чтобы не парсить его дважды
# Затем запустить импорт — обработаются все *_part001.json, *_part002.json, ...
python auto-import-data.py
```

Опции скрипта:
- `--size-mb 150` — размер одной части в МБ (по умолчанию 100)
- `--out-dir data/egr_json_full` — каталог для частей (по умолчанию — каталог исходного файла)

После разбиения в каталоге появятся файлы вида `имя_part001.json`, `имя_part002.json` и т.д.; импорт подхватит их автоматически.

## Примечания

- **Обогащение через API занимает время**: для 10000 записей может потребоваться несколько часов
- **Rate limiting**: EGR API имеет ограничения на количество запросов
- **Кеширование**: повторная обработка уже обогащенных записей не требует новых API запросов
- **Обработка ошибок**: записи с ошибками обогащения помечаются в `last_error`
