# Б24: установка после перехода на company.tenders.by

## Что подтверждено 14.09.2026

- Production API использует `APP_URL=https://company.tenders.by` и такой же `TENDEX_API_URL`.
- В логах в 16:31–16:33 по Минску установка обращалась к отключённому `test.tendex.by` и получала 502.
- В 16:36 production зарегистрировал события создания/обновления компаний на `company.tenders.by` и сохранил установку `autocrm.bitrix24.by`.
- Значения основного и установочного URL непосредственно в карточке Б24 не проверены: текущий REST access token при диагностике уже истёк. Токены не обновлялись и настройки портала не менялись.
- Прямое открытие `/bitrix/admin/` без авторизационного POST из Б24 возвращает 400 — это ожидаемо, а не проверка успешной установки.

## Что поправлено локально

1. После успешной регистрации событий вызывается только `BX24.installFinish()`. Убрана дополнительная переадресация на `/bitrix/admin/`, терявшая авторизацию.
2. Ошибка регистрации событий теперь останавливает завершение установки; сохранение настроек тоже не показывает ложный успех.
3. Повторная установка проверяет существующие подписки. На production сначала подтверждаются оба production-обработчика, затем удаляются только точные старые online-подписки этого приложения на `https://test.tendex.by/bitrix/webhook/company-update`. Другие пути/события и offline-подписки не удаляются. Dev не удаляет production-подписки.
4. SDK загружается один раз, до скрипта завершения установки.
5. При первичном открытии админки сохраняется домен портала, а не только токены.
6. API и Nginx разрешают встраивание `/bitrix/` для поддерживаемых облачных порталов `.bitrix24.by`, `.ru`, `.com`, `.kz`. Остальные страницы не открываются для внешнего iframe. Установочные запросы проверяют домен портала, права администратора и совпадение хоста с APP_URL. Коробочные Б24 и другие доменные зоны этим исправлением не поддерживаются.

Миграций БД и изменений фронтенд-сборки в этом исправлении нет.

## Обязательно проверить карточку production-приложения

Администратор `autocrm.bitrix24.by` должен открыть настройки **существующего локального приложения** и проверить оба поля:

| Поле | Значение |
| --- | --- |
| Путь вашего обработчика (основной адрес) | `https://company.tenders.by/bitrix/admin/` |
| Путь для первоначальной установки | `https://company.tenders.by/bitrix/install` |

Не создавайте замену production-приложению и не удаляйте его ради смены URL: у нового приложения будут другие OAuth-реквизиты. Не публикуйте секреты/токены в чате или логах.

Сам push эти поля не исправит. `BX24.installFinish()` открывает основной обработчик из настроек Б24:
https://apidocs.bitrix24.com/sdk/bx24-js-sdk/system-functions/bx24-install-finish.html

## Порядок проверки: dev → production

1. Отдельный коммит только с исправлением Б24; CI и локальные тесты.
2. По согласованию временно поднять dev API, БД и Redis. Dev сейчас намеренно выключен из-за ограничений RAM; не запускать парсеры/Elasticsearch для этой проверки.
3. Учесть, что оба домена обслуживает общий Nginx: обновление заголовков не происходит от пересборки одного dev API. Перед согласованным reload проверить `nginx -t`; не перезапускать production-стек целиком.
4. Проверять на отдельном тестовом портале/тестовом локальном приложении, с отдельными OAuth-реквизитами и dev БД. **Не переводить существующее production-приложение autocrm на test.tendex.by.** На одном dev-портале поддерживается одна запись настроек; два приложения одного портала в одной БД будут конфликтовать.
5. Dev-пути: `https://test.tendex.by/bitrix/install` и `https://test.tendex.by/bitrix/admin/`. Установить из Б24, убедиться, что админка открылась без 400/502/ошибки iframe. Сохранить настройки с правами CRM; проверить создание и изменение отдельной тестовой компании с УНП, заполнение реквизитов. После повторной установки не должно быть повторных подписок с тем же URL.
6. Только после этой проверки перенести **один Б24-коммит** в `main` (cherry-pick/отдельный PR), затем обновить production API и согласованно перечитать Nginx. Не сливать весь develop: там есть отдельные коммиты по судам; изменения парсеров также не относятся к этому исправлению.
7. Проверить оба production-пути в карточке autocrm, открыть приложение из Б24, повторить установку/сохранение настроек для восстановления обработчиков. Проверить тестовую CRM-компанию, отсутствие обращений этого приложения к test.tendex.by и повторное открытие после обновления OAuth-токена.
8. По окончании тестов снова остановить dev без удаления volumes.

Локальные mocked-тесты не заменяют проверку настоящей установки и Nginx. На сервере это исправление пока не применено.

## Что включить в коммит

Выполнить локально из корня репозитория, когда принято решение коммитить. Не использовать `git add .`:

```bash
git add app/bitrix/admin.py app/bitrix/install.py app/bitrix/security.py app/bitrix/templates/base.html app/bitrix/templates/install.html app/main.py tests/test_bitrix_installation.py docs/BITRIX_DOMAIN_FIX.md
git add -p nginx/conf.d/company.tenders.by.conf
git diff --cached --stat
git diff --cached
```

В `git add -p` выбрать добавление `map` и две замены `Content-Security-Policy`. Отклонить отдельный hunk Grafana `burst=20 → burst=180` — это прежнее изменение, не часть Б24. Убедиться, что в индексе нет ранее добавленных посторонних файлов.

После проверки состава:

```bash
git commit -m "Fix Bitrix installation and production domain handlers"
git push origin develop
git log -1 --oneline
```

Этот push — для dev/CI, не разрешение выкатывать production. Перед переносом в main обновить remote refs и использовать хеш именно этого коммита. Незакоммиченные файлы парсеров оставить на месте, не делать reset/clean/stash без необходимости.

Проверка:

```bash
python -m pytest tests/test_bitrix_installation.py -q
python -m pytest tests -q
```

Результат локально: 35 тестов Б24 и 173 теста всей папки `tests` прошли; присутствуют предупреждения об устаревших API зависимостей. Nginx runtime-проверка и реальный тест в портале ещё не выполнены.
