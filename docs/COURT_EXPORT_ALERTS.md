# Уведомления об отказе авторизации суда

Экспортёр `scripts/export_court_judgments.py` сохраняет JSONL и checkpoint.
Импорта этих файлов в PostgreSQL и привязки к компаниям по УНП пока нет:
наличие миграции `court1schema` само по себе данные не загружает.

## Включение Telegram

Добавить к запуску экспортёра `--notify-telegram`, а в окружение контейнера:

- `ALERT_TELEGRAM_BOT_TOKEN` — токен существующего бота уведомлений;
- `ALERT_TELEGRAM_CHAT_ID` — ID чата, получающего уведомления.

Хранить значения в закрытом env-файле вне Git (права `0600`), указав
дополнительный `env_file` для сервиса в отдельном Compose override:

```yaml
services:
  api:
    env_file:
      - /home/user/egr-secrets/court-alerts.env
```

Передавать этот override дополнительным `-f` после основного Compose-файла.
Не помещать значения токена в команды, логи или сообщения.

Это отдельный opt-in механизм, не зависящий от `PARSER_ALERTS_ENABLED`:
dev Compose отключает общие Celery-оповещения, но явно включённое уведомление
экспортёра всё равно должно отправляться. Другие парсеры оно не включает.
При отсутствии переменных запуск с флагом завершается до запроса к судам.

Когда сайт возвращает распознанную ошибку авторизации (в том числе редирект
`/Account/Login` или `/ru/account/login`, login-форму, HTTP 401/403), экспортёр:

1. Сохраняет ранее записанные JSONL и checkpoint.
2. Один раз пытается отправить сообщение в Telegram (таймаут 8 секунд,
   без повторов и редиректов).
3. Пишет в stderr `Court Telegram notification: sent` либо `NOT delivered`.
4. Завершается с кодом `2`; цикл `sh -ec` не запускает следующие типы актов.

Сообщение содержит ID суда, TypeProc и число уникальных записей текущего
файла. Cookies, токены и тела ответов сайта не отправляются. Отказ Telegram
не отменяет остановку и не удаляет прогресс. Доставка best-effort, не гарантия.

Это уведомление по факту отказа **на следующем запросе**, а не прогноз срока
жизни cookie. Не оповещает об OOM, аварии сервера или других ошибках парсинга.

## Уже запущенный контейнер

Изменения локального кода не включают уведомления на сервере автоматически.
После доставки этих файлов надо завершить/остановить старый экспорт и создать
контейнер с новым флагом и окружением. Обычный `docker start` не меняет команду
и переменные существующего контейнера. Не запускать два экспортёра одновременно.

Оставить прежние каталог `/home/user/egr-court-exports/volume-check`, cookie,
даты и фильтры: тогда новый процесс продолжит checkpoint без повторного сбора
завершённых страниц. Не удалять `.jsonl.partial`, `.state.json` и rate-state.
При остановке посреди записи документа/страницы может потребоваться отдельная
проверка целостности; предпочтительно переключение после штатного выхода.
