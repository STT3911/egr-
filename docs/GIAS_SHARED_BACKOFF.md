# Общая пауза индекса ГИАС

Ошибки ReadTimeout и HTTP 503 относятся к недоступности внешнего источника.
Раньше повтор конкретной Celery-задачи ждал 300 секунд, но beat успевал создать
новую задачу каждые две минуты. Она начинала запросы независимо от этой паузы.

Теперь `sync_gias_contract_index` получает отдельную PostgreSQL advisory-lock
на всё время импорта и использует `egr_system_state.gias_contract_index_cooldown_v1`.
После последовательных сетевых ошибок пауза общая: 300, 600, 1200 секунд,
затем максимум 1200. Успешный импорт сбрасывает счётчик.

- Новые задания во время паузы возвращают `status=cooldown`, без запросов ГИАС.
- Конкурентный импорт возвращает `already_running`.
- Старый повтор после успеха/смены владельца возвращает `superseded_retry`.
- Эти три результата не отправляются как «успешная синхронизация» в Telegram.
- Курсор импорта, зафиксированные страницы и бизнес-данные не сбрасываются.
- Ошибка координации в БД останавливает задание до сетевого обращения.
- HTTP retry внутри одного запроса остаётся прежним; устранена конкуренция
  повторов разных заданий. Устранить таймауты самого gias.by этим нельзя.
- Новая миграция не нужна. Нужно обновить код и перезапустить worker heavy,
  предварительно дождавшись завершения его активной задачи. Не останавливать
  БД, Bankrot, API или beat ради этого исправления.

Проверка после выкладки: успешный sync, значение указанного SystemState и
результаты cooldown при следующем внешнем сбое. Не вызывать искусственно
ошибки ГИАС и не удалять сохранённые курсоры.
