# Consolidated backend release, 20 October 2026

This release records the previously deployed hotfixes in Git so that develop and
main can be advanced to the same tested source tree. Do not copy `.env`, cookies,
Docker Compose overrides, database files, or checkpoints between environments.

## Contents

- EGR: bounded daily-source retries, durable source-outage state, exact duplicate
  base-card handling, lossless reconciliation of incomplete IP-to-company links.
  New days continue while unresolved observations remain visible for reconciliation.
- GIAS: one importer at a time, shared persisted cooldown, obsolete-retry suppression.
- Courts: separate authentication and ordinary-error notifications; authorized
  text/file cookie renewal; resumable blank-response recovery. The requested
  interval is 30 seconds, with 10 records per page. Do not change the page size
  while resuming an existing numbered-page checkpoint.
- Bankrot: verified compression of completed snapshots and deduplicated manager
  blobs; retain all completed snapshots by default and preserve active `.tmp` files.
- Monitoring: processing coverage and fully reconciled coverage are separate;
  unresolved queues remain visible. Preserve the production Grafana burst setting.
- Container: permit a host-mapped UID to traverse the Python package directory
  without making the application user's home listable or writable.

No dependency or migration changes are introduced by this release. Existing
production Bitrix landing/install handlers are retained, including their tests.

## Acceptance and deployment order

1. Run the complete offline test suite on the consolidated commit, not only on
   the original dirty checkout. Check one Alembic head and compare it to both DBs.
2. Fetch the exact commit on the server. Before adopting pre-existing hotfixes,
   back up only the affected source/configuration files, their permissions, Git
   revision/index and the list of image IDs. Reject unexpected local changes.
   Never stash/remove untracked modules while a bind-mounted application runs.
3. Build a backend image from `git archive` of that commit (no server secrets or
   mutable data in the build context). Deploy the image to dev with dev's existing
   environment/network/database. Verify readiness, imports and migration revision.
4. Promote that same commit to main after dev acceptance. Production retains its
   own Compose file, environment, database volumes, TLS, and Grafana state.
5. Pause beat before draining consumers. Use warm shutdown and a bounded wait;
   do not kill active Bankrot tasks or reset pipeline cursors to accelerate release.
   If draining fails, stop promotion and restore the scheduler deliberately.
6. Recreate only backend services using the verified image. Keep DB, Redis,
   Elasticsearch, frontend, nginx, Grafana and the court exporter intact unless a
   verified configuration difference specifically requires a reload.
7. Verify public readiness, backend task registration, DB revision, EGR coverage
   and controller health. A private cookie prompt is sent only for confirmed auth
   failure; a source outage is not a successful import.

## Rollback

Keep the pre-release source/configuration copy and immutable image IDs in the
server's release backup directory. Restore the recorded affected source files and
previous image IDs, then warm-restart only the changed backend services. With no
schema change, no database downgrade is needed. Do not roll back database records,
source queues, cookie/controller state, JSONL or court checkpoints. Restore the
scheduler after backend health is confirmed. Never use `down -v` or volume pruning.

## Remaining external limits

The release does not repair GIAS availability or guarantee a court session's
lifetime. The court job is still its existing economic-court JSONL export through
15 September 2026, not a complete-current-history ingestion into PostgreSQL.
Incomplete official EGR links remain unresolved rather than inventing identifiers.
