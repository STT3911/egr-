# Исправления периодических загрузчиков

Локальные изменения от 14.09.2026. На сервер автоматически не устанавливались.
МАРТ остаётся ручным импортом CSV; ГИАС этим изменением не затрагивается.

## Что изменено

- ЕГР Mobile и ГРП: таблица `source_fetch_attempts` хранит результат попытки,
  время проверки и `next_check_at` отдельно от реальных адресов/плательщиков.
  Пустые ответы не создают фиктивные данные и не стирают ранее полученные.
  Пакет распределяется между новыми УНП, перепроверкой старых записей и повторами.
  Сбой низких УНП больше не блокирует продвижение следующих.
- ГРП: исправлено обновление `fetched_at` при разборе успешного raw-ответа;
  используется время получения данных, а не время повторного разбора.
- Лицензии: плановая задача обходит страницы порциями, сохраняя
  `license_check_next_page` в `egr_system_state` после импорта страницы.
  При ошибке повторяет эту страницу, в конце начинает новый проход.
  Явно переданное `pages` сохраняет режим ручной проверки первых N страниц.
  Источник использует меняющуюся нумерацию страниц: один проход не является
  гарантированным согласованным снимком; регулярные повторные проходы нужны.
- Telegram: результат `source_empty`/`source_unavailable`/`snapshot_fallback`
  показывается предупреждением, а не зелёным сообщением об успешном обновлении.
- МНС: канонический адрес — `https://lkfl.portal.nalog.gov.by/debtor/`.
  Пустой текущий срез не перезаписывает хороший JSON и не очищает БД.
  Задача пробует обновить непосредственно предыдущий месяц, сохраняя его дату,
  и возвращает `source_empty`, а не сообщает об актуальном текущем месяце.
  Если оба месяца пусты, импорт не выполняется; ошибки транспорта не маскируются.
  Импорт ограничен одной конкретной датой; посторонний более новый файл не выбирается.
  Вставки разбиты по 1000 строк, но замена среза остаётся одной транзакцией.
  Остальные месяцы истории не удаляются. При исторической выгрузке пустые месяцы
  явно пропускаются с предупреждением и без создания пустых файлов.
- СЭЗ: при недоступном источнике майский снимок больше не импортируется поверх БД.
  Фоновые задачи и служебное состояние явно сообщают о недоступности источника.
  Ручной импорт сохранённого снимка остаётся доступен отдельным CLI.

## Ограничения внешних источников

14.09.2026 двумя контрольными запросами МНС с `lmt=1` проверено:
01.09.2026 — пустой ответ, 01.08.2026 — строка данных. Это не доказательство
отсутствия задолженности в сентябре. Дата в имени файла не сдвигается искусственно.

Официальный каталог `https://opendata.eaeunion.org/opendata/` для резидентов СЭЗ
ссылается на `https://nsi.eaeunion.org/portal/1993`, который перенаправил на
`https://customs.eaeunion.org/registers/04` и вернул HTTP 403 при контрольной проверке.
Старый XML broker и указанный в каталоге OData PCC03 возвращают 404.
Свежая выгрузка СЭЗ поэтому НЕ восстановлена: требуется доступный официальный
источник/выгрузка. Обход ограничений доступа не выполняется.

## Параметры

| Настройка | По умолчанию | Значение |
|---|---:|---|
| `GRP_REFRESH_DAYS` | 30 | Возраст для повторной загрузки плательщика |
| `GRP_EMPTY_RETRY_DAYS` | 7 | Пауза после отсутствия плательщика |
| `GRP_FETCH_RETRY_COOLDOWN_MINUTES` | 30 | Пауза после ошибки |
| `PLACE_LOCATION_REFRESH_DAYS` | 90 | Возраст для перепроверки адреса |
| `PLACE_LOCATION_EMPTY_RETRY_DAYS` | 7 | Пауза после пустого адреса |
| `PLACE_LOCATION_ERROR_RETRY_MINUTES` | 60 | Пауза после ошибки адресного API |
| `LICENSE_CHECK_PAGES` | 10 | Максимум страниц за один плановый запуск |

Периоды — критерии отбора, не гарантия обновления всей базы за указанное число дней.
Скорость полного обхода ограничена размером пакетов и существующим расписанием.
Частота запросов и параллелизм адресов/ГРП автоматически не увеличивались.

## Проверка и установка

1. Сначала проверить изменения на dev/изолированной PostgreSQL, не запускать
   массовые выгрузки на production. SQLite-тесты не заменяют проверку плана
   выборки на большом объёме PostgreSQL.
2. Новому коду требуется миграция `sourcefetch1` (после `court1schema`). Она
   добавляет только таблицу учёта попыток и индекс, не меняет бизнес-таблицы.
   Не запускать новые воркеры до миграции. На production ещё может быть
   `addrunit1`: сначала проверить цепочку миграций, не пропускать её через stamp.
3. После доставки проверенной версии пересобрать API/воркеры; расписание
   лицензий читается из настроек. Git push, сборки, миграции и перезапуски
   этой локальной правкой не выполняются.

Локальные тесты (без запросов к сайтам и production БД):

```bash
python -m pytest tests -q
```

Наблюдение после установки (SQL только чтение):

```sql
SELECT source, status, count(*) AS attempts,
       max(checked_at) AS last_attempt, min(next_check_at) AS next_check
FROM source_fetch_attempts GROUP BY source, status ORDER BY source, status;

SELECT key, value FROM egr_system_state
WHERE key IN ('license_check_next_page', 'source_health:nalog_debt', 'source_health:eaeu_sez');

SELECT status, started_at, finished_at, last_page, processed_records, stats_json
FROM license_sync_runs ORDER BY started_at DESC LIMIT 5;
```

`source_health:*` различает время попытки и результат. Общая таблица Grafana
по-прежнему измеряет дату записей и красит все источники после 48 часов:
не считать её индикатором успешности задачи или полноты текущего месяца.
