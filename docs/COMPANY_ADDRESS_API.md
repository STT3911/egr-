# Адреса профиля компании

`GET /api/v1/companies/{unp}` возвращает адреса в `addresses`, включая компании,
для которых сохранён адрес ГРП, но не загружена история адресов ЕГР.

Приоритет данных:

1. Если есть непустые адреса истории ЕГР, ответ содержит эти записи с исходными
   датами и `source: "egr"`. Адрес из `place_location_address` их не подменяет.
2. Если истории нет, ответ содержит сохранённый адрес из
   `egr_company_place_locations`. `source` отражает метку `grp`, `gias` или ЕГР.
   Неизвестный источник обозначается `null`.
3. Если ни одного адреса нет, возвращается `addresses: []`.

Пример для УНП 400047301 в dev:

```json
{
  "full_address": "Гомельская обл., Терешковичский с/с, аг. Терешковичи",
  "postal_code": null,
  "region": "Гомельская",
  "district": null,
  "valid_from": null,
  "valid_to": null,
  "source": "grp"
}
```

Для запасного адреса даты действия неизвестны: дата регистрации компании и дата
получения данных не используются как дата смены адреса. Запись формируется при
чтении и не добавляется в историю ЕГР или в ленту событий.

Поле `region` сохраняет значение источника. Если оно пустое, можно использовать
явно указанную область из текста адреса либо `г. Минск`. Другие города не
преобразуются в области по предположению. При отсутствии однозначных данных
остаётся `null`. Индекс и район запасного адреса также извлекаются только из
явно указанных компонентов.

`place_location_address` сохраняется для совместимости. Поле `source` в элементах
`addresses` добавлено как необязательное. Кэш профиля переведён на версию v11,
чтобы старый ответ с пустым массивом не скрывал исправление.

Это поведение также используется в `/api/v1/companies/public/{unp}`.
Отдельный контракт `/api/v1/stable/companies/{unp}` этим изменением не затронут.
